# 実験I-C・共有推定器が作る方策遷移障壁 v0.2.2

実験I-C v0.2.1では、400反復時点でOracleに達していなかった24条件のうち、23条件が長期継続・Adam状態リセット・方策再加熱・微小摂動後にも安定点候補として残りました。v0.2.2は、その安定性を生んだ計算機構を直接測ります。

## 問い

より良い観測方策が一ビット隣に存在するのに、なぜ共同更新は現在の方策から離れられないのでしょうか。

本実験では、二つの決定的な観測方策の間で、一時刻の観測確率だけを連続的に動かします。その途中で推定器をどう扱うかについて、二条件を比較します。

- **共有推定器**：混合した観測分布全体に一つの推定器を当て直す
- **専用推定器**：各決定的方策がそれぞれの最適推定器を持つ

## 測定する量

出発方策を (s)、到着方策を (t)、到着方策の混合率を \(\alpha\) とします。

共有条件は、

```text
J_shared(alpha) = min_W [(1-alpha)L_s(W) + alpha L_t(W)]
```

専用条件は、

```text
J_dedicated(alpha)
  = (1-alpha) min_W L_s(W) + alpha min_W L_t(W)
```

です。一般に、和を取ってから一つの推定器を最適化する共有条件は、各項を別々に最適化できる専用条件以上の損失になります。その差を**混合ペナルティ**と呼びます。

到着方策の方が良くても、混合ペナルティが十分に大きければ、目的値は一度上昇してから下降します。この上昇分が**方策遷移障壁**です。

## 実験範囲

- 時間相関 `phi`：0.0、0.4、0.8
- 評価重み `lambda`：0.25、0.5、0.75
- 方策：長さ4のA/Bスケジュール全16通り
- 遷移：Hamming距離1で、到着点の方が良い全32辺
- `--quick`：各経路を101点で走査
- `--full`：各経路を1001点で走査

母集団共分散を使うためseedはありません。有限標本の揺らぎではなく、モデル構造そのものを測ります。

## full結果

`phi=0`では、全評価重みで改善辺32本中の障壁は0本でした。`phi=0.8`では障壁が16〜18本に現れ、`lambda=0.5`では18/32本、最大障壁は0.039801でした。

方策ごとに専用推定器を与える対照では、すべての経路が端点間の直線となり、障壁は0でした。したがって今回の障壁は、時間的に相関した観測のもとで、一つの推定器が複数の観測分布へ同時に適応することから生じています。

## 理論上の意味と限界

この結果が分離したのは、現在の観測方策に推定機構が専門化し、その専門化が別の方策への離脱費用を作る成分です。

推定器は各混合率で最適に当て直され、過去の観測履歴を重みに蓄積していません。したがって、観測頻度の反復が表現解像度を履歴依存的に固定する不可逆性は、まだ扱っていません。これは後続の実験IIで検証する成分です。

また、`phi=0`で混合ペナルティが数値精度内の0になることから、混合ペナルティは将来の環境でも、観測パターン間の結合が実際に効いているかを調べる診断量として利用できます。

ただし、単一の線形共有推定器を仮定した人工系での結果です。「共有推定器」は人間の共有表現体系そのものではありません。また、専用推定器条件はMixture-of-Expertsに近い極端な上限です。部分共有モデルが中間的な障壁を持つかは、今後の検証課題です。
