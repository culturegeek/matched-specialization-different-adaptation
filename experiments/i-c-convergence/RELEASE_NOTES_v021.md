# Release notes v0.2.1

## 目的

実験I-C v0.2で共同更新方策がOracle以外へ収束した原因を、静的局所最適、共同更新の安定点、反復不足、softmax方策の捕捉へ分解する。

## 追加した測定

- 400・800・1600・3200反復のチェックポイント
- logit勾配ノルム
- 方策エントロピー
- 確率境界における別行動への改善余地
- argmaxスケジュールの遷移履歴
- Adam状態リセット対照
- 2倍・4倍の方策再加熱
- 再加熱後の微小摂動対照
- 母集団の静的局所最適との照合

## full結果

- 400反復時点でOracle：36/60
- 母集団の静的局所最適ではない共同更新安定点候補：22/60
- 静的局所最適と共同更新安定点候補の一致：1/60
- 強い方策再加熱による脱出：1/60
- 単純継続で初めてOracleへ到達：0/60

## 解釈

v0.2の非Oracle方策は、全体として単純な反復不足ではなかった。多くは、その方策に適応した推定器との組み合わせにおいて局所的な改善方向を失い、強い再加熱や摂動後にも同じ方策へ戻った。

この結果は共同更新が複数の吸引域を持ちうることを示す構成的証拠だが、数学的な固定点の証明でも、人間の志向性の証明でもない。
